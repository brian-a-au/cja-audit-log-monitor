- **Breaking.** The tool now takes the four credential fields (`org_id`, `client_id`, `secret` and `scopes`) from one place and never mixes two places. Before, it took each field from the highest place that had it, e.g. three fields from the environment and the secret from the config file. To fix a setup that mixed places, put all four fields in one place. `cja-audit-log-monitor cli config` shows which place the tool uses.
- **Breaking.** A place that holds some of the four credential fields and not all of them is now an error that names the missing fields. The tool does not go on to a lower place. To fix it, add the missing fields there, or remove the fields that are set there, e.g. `unset CLIENT_ID`.
- **Breaking.** The tool no longer has built-in scopes. Before, a credential without scopes used `openid,AdobeID,read_organizations,additional_info.projectedProductContext`. A credential without scopes is now an error that names `scopes`. To fix it, copy the scopes from the credential page in the Developer Console into `SCOPES`, or into `scopes` in your profile or config file.
- **Breaking.** A credential in the config file you give with `-c` now wins over the environment variables and `.env`. Before, the environment variables and `.env` won. Remove the credential fields from that file if you want the environment variables to be used. A `-c` file with no credential fields works as before. Every other setting still comes from the environment variables first, then `.env`, then the config file.
- **Breaking.** The tool now reads the `CJA_PROFILE` environment variable. When it is set, the credential comes from that profile, and the profile wins over the environment variables, `.env` and the default config file. Unset `CJA_PROFILE` if you set it for another tool and do not want it here.
- **Breaking.** The TUI no longer opens when the config file cannot be read or holds an invalid setting. Before, it opened with the settings from the environment variables and `.env`, and showed a warning in the header. It now prints one line that starts with `Configuration error:` and names the file, as the CLI does. Fix the file and start the TUI again.
- **Breaking.** `cli verify -F json` has a new shape, `adobe-credentials/v1/live-test`, which the Adobe tooling repos share. The keys `connected`, `authenticated` and `error` are gone. Read `ok`, `sign_in` and `product_access` in their place. `org_id`, `api_url` and `total_logs_available` are kept.
- `cli verify` with no credential now prints `Configuration error: No credential was found.` on stderr and the ways to give one. Before, it printed `Authentication failed: OAuth not configured` on stdout. It still exits 1.
- The client ID is now shown as its first 4 and last 4 characters, e.g. `aaaa****4444`, in `cli config` and in the TUI config view. Before, `cli config` showed the first 8 characters and the TUI showed the first 12. A client ID of 8 characters or fewer shows as `****`.
- The "OAuth not configured" error now lists every way to give a credential.
